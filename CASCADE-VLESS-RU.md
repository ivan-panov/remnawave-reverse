# Автоматизация каскада VLESS IN → VLESS OUT

Модифицированная сборка добавляет в главное меню пункт:

```text
12. Серверный роутинг — каскад VLESS IN → VLESS OUT
```

## Что создаётся автоматически

Модуль работает через локальный API Remnawave и:

1. предлагает выбрать входную и выходную ноды;
2. требует, чтобы ноды использовали **разные Config Profile**;
3. сохраняет полный JSON обоих профилей и активные inbound-теги для отката;
4. добавляет в профиль выходной ноды служебный VLESS + REALITY inbound;
5. создаёт Internal Squad и бессрочного служебного пользователя;
6. добавляет в профиль входной ноды VLESS + REALITY outbound;
7. добавляет правила маршрутизации только для выбранных inbound'ов;
8. перезапускает ноды и сохраняет состояние интеграции.

Профили обновляются **на месте**, а не клонируются. Это необходимо, потому что Remnawave требует глобально уникальные inbound-теги и может отклонить полный клон активного профиля.

## Режимы маршрутизации

- весь трафик выбранных inbound'ов через выходную ноду;
- российские IP и домены через входную ноду, остальной трафик через выходную.

## Установка

Распакуйте актуальный архив и выполните:

```bash
cd remnawave-reverse-3.0.11
chmod +x install_remnawave.sh
sudo ./install_remnawave.sh
```

После установки команда запуска:

```bash
rr
```

## Firewall выходной VPS

Модуль не имеет SSH-доступа к выходной VPS, поэтому межсерверный TCP-порт нужно разрешить на самой выходной ноде. Желательно только для IP входной VPS:

```bash
sudo ufw allow from ENTRY_VPS_IP to any port 8443 proto tcp comment 'Remnawave VLESS cascade'
sudo ufw status numbered
```

## Откат и удаление

Пункт «Отключить» восстанавливает исходную конфигурацию входного профиля, оставляя служебный bridge на выходной ноде для быстрого повторного включения.

Пункт «Удалить»:

- восстанавливает исходный JSON и активные inbound'ы обеих нод;
- удаляет служебного пользователя;
- удаляет Internal Squad;
- удаляет state-файл интеграции.

Состояние хранится в:

```text
/usr/local/remnawave_reverse/cascade_vless/state.json
```

Состояния старого формата v2 с клонированными профилями продолжают поддерживаться для отключения и удаления. Новые установки создают state v3 с режимом `in_place`.

## Обновления

Встроенное обновление загружает основной скрипт, оба языка, все Nginx/Caddy-модули, API-модуль, tools и закреплённый launcher AmneziaWG. Перед заменой shell-файлы проходят `bash -n`; при ошибке текущие файлы сохраняются.
## Совместимость с Remnawave backend:3

Начиная с 3.0.13 каскад не требует, чтобы create-endpoint немедленно возвращал UUID в теле ответа. Internal Squad подтверждается через повторный GET, а UUID служебного пользователя и VLESS UUID задаются установщиком заранее и проверяются после создания. Это предотвращает ложный rollback при асинхронном/пустом успешном ответе API.


## Совместимость с Remnawave Panel v3

В Panel v3 пользователь идентифицируется числовым `id` (`userId`). UUID аккаунта больше не используется как ключ `GET/DELETE /api/users/{...}`. Каскад 3.0.13 создаёт служебного пользователя без поля `uuid`, получает его через `/api/users/by-username/{username}`, сохраняет `userId` и отдельно использует `vlessUuid` как VLESS credential. Членство в служебном Internal Squad обязательно проверяется и при необходимости назначается через `bulk-actions/add-many-users`.
