## Обзор

`remnawave-reverse` автоматизирует установку и управление:

- Remnawave Panel и Remnawave Node;
- реверс-прокси NGINX или Caddy;
- Subscription Page и SelfSteal для VLESS REALITY;
- SSL-сертификатами, UFW, IPv6 и вспомогательными функциями WARP;
- серверным VLESS-каскадом между нодами Remnawave;
- входом AmneziaWG 3.0 с передачей трафика в Remnawave/Xray;
- ручным и опциональным плановым обновлением контейнеров.

Xray может работать непосредственно на порту 443 и передавать веб-трафик реверс-прокси через Unix-сокет, без лишнего TCP-проксирования.

## Возможности актуальной модифицированной сборки

### Предварительная проверка Docker

Перед установкой Remnawave скрипт проверяет:

- Docker Engine;
- состояние Docker daemon;
- Docker Compose v2;
- возможность запуска тестового контейнера.

На поддерживаемых версиях Ubuntu отсутствующие или повреждённые компоненты Docker могут быть установлены из официального APT-репозитория Docker, после чего установка Remnawave продолжается автоматически.

### Актуальные ветки контейнеров

Новые установки используют поддерживаемые ветки приложений:

```yaml
remnawave/backend:3
remnawave/subscription-page:latest
remnawave/node:latest
nginx:stable        # режим NGINX
caddy:2             # режим Caddy
valkey/valkey:9-alpine
```

PostgreSQL в создаваемом Compose закреплён на конкретной версии. Мажорное обновление базы данных нельзя выполнять как обычное автоматическое обновление контейнера.

### Серверный VLESS-каскад

Пункт меню **12** создаёт и обслуживает через API Remnawave маршрут:

```text
Клиент → публичный VLESS inbound входной ноды
       → VLESS + REALITY outbound
       → служебный VLESS inbound выходной ноды
       → прямой выход в интернет с выходной ноды
```

Автоматизация клонирует оба Config Profile, создаёт служебные Internal Squad и пользователя, назначает профили, перезапускает ноды и сохраняет данные для отката. Поддерживаются:

- отправка всего трафика выбранных inbound через выходную ноду;
- российские направления напрямую через входную ноду, остальной трафик через выходную;
- проверка состояния;
- отключение и повторное включение;
- полное удаление с восстановлением исходных профилей.

Подробнее: [CASCADE-VLESS-RU.md](./CASCADE-VLESS-RU.md).

### Вход AmneziaWG 3.0

Пункт меню **13** интегрирует трафик AmneziaWG с выбранным outbound Remnawave:

```text
Клиент AmneziaWG → awg0 на локальном VPS
                  → прозрачный перехват TCP/UDP
                  → Remnawave Node / Xray
                  → выбранный outbound, включая VLESS-каскад
```

Встроенная интеграция использует исходники `bivlked/amneziawg-installer` v5.24.0, закреплённые в модифицированной сборке. Для гарантированной установки AWG 3.0 требуется совместимый VPS `x86_64` и ядро Linux 6.7 или новее. Модуль блокирует незаметный переход на AWG 2.0.

Подробнее: [AMNEZIAWG3-REMNAWAVE-RU.md](./AMNEZIAWG3-REMNAWAVE-RU.md).

### Обновление контейнеров

Модуль управления умеет:

- показывать настроенные образы и состояние контейнеров;
- создавать резервную копию перед обновлением;
- после подтверждения переводить существующий Compose Panel 2 на Panel 3;
- выполнять `docker compose pull` и пересоздавать сервисы;
- включать и отключать еженедельный systemd-таймер обновлений;
- сохранять журнал обновления.

Подробнее: [CONTAINER-UPDATES-RU.md](./CONTAINER-UPDATES-RU.md).

## Поддерживаемые схемы установки

### 1. Панель и нода на одном VPS

Подходит для тестирования и небольших установок. Скрипт выводит предупреждение, поскольку для рабочей инфраструктуры предпочтительно размещать Panel и Node отдельно.

### 2. Распределённая установка

- **VPS панели:** Remnawave Panel, база данных, кеш, Subscription Page и реверс-прокси.
- **Входной VPS-нода:** Remnawave Node, к которой подключаются клиенты.
- **Выходной VPS-нода:** необязательная выходная нода для VLESS-каскада.

Модуль каскада запускается на VPS панели после подключения обеих нод и назначения им активных Config Profile.

## Требования

- права root;
- чистый VPS с Debian или Ubuntu; основной проверенный вариант модифицированной автоматизации — Ubuntu 24.04;
- KVM или другая виртуализация с поддержкой необходимых функций ядра и сети;
- Docker Engine и Docker Compose v2 либо разрешение скрипту установить их на Ubuntu;
- собственные домены с заранее настроенными DNS-записями;
- достаточные CPU, RAM и место на диске для выбранной схемы Panel/Node;
- snapshot или внешняя резервная копия перед мажорными обновлениями и изменением маршрутизации.

Для интеграции AmneziaWG 3.0 дополнительно проверьте:

```bash
uname -m
uname -r
```

Строгий режим AWG 3.0 ожидает `x86_64` и ядро Linux `6.7+`.

## Требования к доменам

Подготовьте до трёх доменов или поддоменов:

1. **Домен панели** — интерфейс управления.
2. **Домен подписок** — страница конфигураций клиентов.
3. **Домен SelfSteal** — маскировочный сайт ноды.

### Пример DNS для одного VPS

| Тип   | Имя               | Значение       | Прокси |
|-------|-------------------|----------------|--------|
| A     | example.com       | IP сервера     | DNS only |
| CNAME | panel.example.com | example.com    | DNS only |
| CNAME | sub.example.com   | example.com    | DNS only |
| CNAME | node.example.com  | example.com    | DNS only |

### Пример DNS для распределённой установки

| Тип   | Имя               | Значение       | Прокси |
|-------|-------------------|----------------|--------|
| A     | example.com       | IP VPS панели  | DNS only |
| CNAME | panel.example.com | example.com    | DNS only |
| CNAME | sub.example.com   | example.com    | DNS only |
| A     | node.example.com  | IP VPS ноды    | DNS only |

## Быстрый старт

Запустите актуальный установщик из этого репозитория:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ivan-panov/remnawave-reverse/refs/heads/main/install_remnawave.sh)
```

Для скачанного ZIP-архива:

```bash
cd /root
unzip -o remnawave-reverse*.zip -d /root/
cd /root/remnawave-reverse*
chmod +x install_remnawave.sh
./install_remnawave.sh
```

> [!IMPORTANT]
> Не используйте `cd` с маской, если в `/root` находится несколько подходящих каталогов. В таком случае укажите точное имя распакованной папки.

## Порядок установки

### Установка только панели

1. Запустите установщик на VPS панели.
2. Выберите **Установка компонентов Remnawave**.
3. Выберите **Установить только панель**.
4. Выберите NGINX или Caddy.
5. Укажите домены панели и подписки, а также данные для сертификатов.
6. Сохраните выданную ссылку доступа к панели и учётные данные.

### Установка только ноды

1. Создайте ноду в Remnawave Panel.
2. Скопируйте её secret key/сертификат в разделе **Ноды → Управление**.
3. Запустите установщик на VPS ноды.
4. Выберите **Установка компонентов Remnawave**.
5. Выберите **Установить только ноду**.
6. Укажите адрес панели, секрет ноды и домен SelfSteal.
7. Проверьте в панели, что нода подключена.

### Панель и нода на одном VPS

1. Запустите установщик.
2. Выберите **Установка компонентов Remnawave**.
3. Выберите **Установить панель и ноду на один сервер**.
4. Подтвердите предупреждение.
5. Выберите NGINX или Caddy и ответьте на запросы установщика.

## Создание VLESS-каскада

Перед запуском:

- входная и выходная ноды должны быть онлайн;
- каждой ноде должен быть назначен активный Config Profile;
- TCP-порт bridge-inbound должен быть разрешён firewall выходного VPS;
- меню нужно запускать на VPS панели.

Откройте меню:

```bash
rr
```

Выберите:

```text
12. Серверный роутинг — каскад VLESS IN → VLESS OUT
1. Создать каскад автоматически
```

Укажите входную и выходную ноды, inbound входной ноды, параметры REALITY и режим маршрутизации. После создания в том же подменю доступны проверка состояния и откат.

## Создание входа AmneziaWG 3.0

Запускайте модуль на VPS, где находятся локальный интерфейс `awg0` и выбранная Remnawave Node:

```bash
rr
```

Выберите:

```text
13. AmneziaWG 3.0 — вход трафика в Remnawave
1. Создать интеграцию автоматически
```

Модуль может установить AWG, продолжить работу после необходимых перезагрузок, создать прозрачный inbound Xray, добавить policy routing и выбрать существующий outbound Remnawave.

Не смешивайте старую интеграцию AWG 2.0 с модулем AWG 3.0. Сначала удалите старую интеграцию через исходную сборку, которой она была создана.

## Управление и обновление контейнеров

Откройте:

```bash
rr
```

Выберите **Управление панелью/нодой**. Доступны запуск, остановка, обновление, логи, CLI, управление доступом к панели, просмотр версий контейнеров и плановое обновление.

Полезные проверки:

```bash
docker ps
docker compose version
cd /opt/remnawave && docker compose config -q
cd /opt/remnawave && docker compose images
```

Для VPS только с нодой:

```bash
cd /opt/remnanode && docker compose config -q
```

## Защита доступа к панели

В режиме NGINX создаваемая конфигурация может защищать панель секретным URL-параметром и cookie. Сохраните точную ссылку, показанную после установки. Без правильного параметра или cookie панель может возвращать пустой ответ или 404.

- Не публикуйте секреты Panel и Node в логах, скриншотах и Issues.
