# Обновление контейнеров Remnawave

Сборка использует поддерживаемые ветки образов:

- `remnawave/backend:3` — актуальная ветка Panel 3.x;
- `remnawave/node:latest` — актуальная Remnawave Node;
- `remnawave/subscription-page:latest` — актуальная страница подписки;
- `nginx:stable` или `caddy:2` — поддерживаемая стабильная ветка reverse proxy;
- PostgreSQL оставлен на явно заданной версии и не обновляется автоматическим модулем.

Перед первым запуском контейнеров установщик выполняет `docker compose pull`.

## Обновление уже установленной Panel 2.x

1. Запустите новую сборку из распакованного каталога. Она обновит файлы команды `rr`.
2. Выполните `rr`.
3. Откройте `Управление панелью/нодой`.
4. Выберите `Обновить панель/ноду`.
5. Подтвердите переход `remnawave/backend:2` → `remnawave/backend:3`.

Перед изменением создаются:

- копия `docker-compose.yml`;
- копия `.env`;
- копия конфигурации Nginx/Caddy;
- дамп PostgreSQL `postgres.sql.gz`.

Резервная копия сохраняется в `/opt/remnawave/backups/update-ДАТА-ВРЕМЯ/`.

## Обычное ручное обновление

`rr` → `Управление панелью/нодой` → `Обновить панель/ноду`.

Обновление выполняется последовательно: Panel → Subscription Page → reverse proxy → Node. После каждого контейнера проверяется состояние/healthcheck. При неуспешном healthcheck модуль пытается вернуть предыдущий Docker image.

Журнал: `/var/log/remnawave-container-update.log`.

## Автоматическое обновление

`rr` → `Управление панелью/нодой` → `Автообновление контейнеров Remnawave`.

Доступны:

1. включить еженедельное обновление;
2. отключить;
3. показать таймер;
4. запустить немедленно.

Таймер выполняется по воскресеньям около 04:15 с случайной задержкой до 30 минут. Мажорный переход Panel 2.x → 3.x автоматическим таймером запрещён и выполняется только вручную.

## VPS с 1 ГБ RAM

При малом объёме доступной памяти модуль временно останавливает Subscription Page и локальную Node перед обновлением Panel, затем запускает и обновляет их последовательно. Во время обновления возможен кратковременный перерыв в работе.
